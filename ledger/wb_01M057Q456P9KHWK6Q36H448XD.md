Field friction 5 (PropertyCompass2 report, PR #2196): every create/transition takes 16-20s wall time on an M4 Max against a ~1,500-item ledger; a 21-create + 6-kill batch with the mandatory per-op commits took ~12 minutes serial. Consumer's unprofiled hypothesis: complete-ledger validation on every mutation, ~1,500 Markdown parses per op - plausible given the architecture (loadedValidLedger parses everything, mutateExistingItem loads at least twice, candidate validation revalidates the complete ledger), but PROFILE FIRST before believing it.

Scope:
1. Build a 1,500-item benchmark fixture and profile one create and one transition; attribute wall time (parse, validate, journal, lock, io).
2. Fix the dominant cost. Candidates, in order of least invasiveness: parse cache keyed on file bytes hash; incremental validation (validate the successor item plus the invariants that reference it - duplicate ids/numbers, relations touching it, epic rollups - instead of the full ledger); avoid the double ledger load per mutation.
3. The complete-ledger safety property must survive: whatever is skipped must be provably unaffected by the mutation, or checked. No correctness regression for speed.

Acceptance:
- Benchmark committed (excluded from default test run) with before/after numbers on the same fixture; target at least 5x on the 1,500-item create path.
- Full suite + conformance green on both runtimes; no validation rule weakened (mutation-guard: a duplicate number or dangling reference introduced by a mutation is still refused on the big fixture).
- Profile findings recorded in the item's decision on close.
