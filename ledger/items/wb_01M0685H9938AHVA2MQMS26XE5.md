Follow-up from item #107: the benchmark's wall-time attribution is unusable on a loaded machine - during #107's run the per-load price swung 321ms to 3,774ms (load average 78-190 from sibling agents), while the load-count attribution stayed exact. The bench currently prints wall times without qualification, inviting before/after comparisons that measure the machine, not the change.

Scope: make bench/mutation-latency.bench.js self-aware about variance. Measure the one-full-load price N times per run; when the spread exceeds a stated factor (e.g. max/min > 1.5), print the wall times flagged as unreliable (or suppress them) and say why, keeping the deterministic counters (ledgerLoadCount, git subprocess counts) as the headline numbers. Record the machine load alongside (os.loadavg).

Acceptance:
- A run under artificial load flags or suppresses its own wall times; a quiet run prints them plainly.
- Counter-based attribution unchanged; the bench stays out of the default test run.
- Gate green on both runtimes.
