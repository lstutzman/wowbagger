# Problem

Pre-publication verification found that the first frozen 1,501-entry mapping used default-history latest-change evidence. A full-history recheck found 262 nonterminal cards with later projected `updated` dates and 264 different source commits. The frozen mapping checksum was `1aacfef22fc73a8a07b79d1a140eb5ee6dcec2c571ce5f62cf7e2ca120dd5a1e`. No target item was published.

The migration agent reverted only its mapping/provision metadata to the pre-freeze checkpoint and discarded every volatile or frozen target ID from the invalid mapping.

# Decision

Derive baseline history only from commits reachable from pinned source commit `8a69e5c61e14416d5e0c60fbebac3f7816e4b84b`. Do not use the current branch default, `--all`, unmerged branch commits, or commits outside that ancestry.

For a missing nonterminal `updated`, use the latest ancestral commit that changed the source path. Apply the approved earliest-evidenced-card-date rule and terminal-state evidence rule inside the same ancestry. Treat the held #1514 delta separately as explicit pre-cutover evidence.

# Acceptance criteria

1. Recovery evidence proves the invalid mapping and provision metadata were removed before target publication.
2. No ID from the invalid mapping is reused.
3. Every Git-derived field cites a commit reachable from the pinned baseline.
4. The report lists all 262 corrected dates and 264 corrected source commits.
5. No derivation uses unrelated or unmerged branch history.
6. The held #1514 delta remains separate from baseline Git history.
7. Verification proves `created <= updated` and terminal date equality across all 1,501 projections.
8. The complete replacement mapping is generated once from corrected evidence, persisted, checksummed, and reused unchanged on retry.
9. No target item is published before the replacement mapping passes.
10. The final target ledger validates.
