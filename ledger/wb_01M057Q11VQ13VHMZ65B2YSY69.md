Field friction 4 (PropertyCompass2 report, PR #2196) and a standing friction from this repo's own dogfooding (2026-08-11 handoff: 'Relations cannot be edited... items filed with depends_on where related was correct cannot be fixed in-band'). Killing an item that another item depends on refuses with `dependent-disposition` - correct guard - but the sanctioned mutation surface offers no way to re-scope the dependent: transition cannot edit relations by contract and patch accepts only priority (number is the immutable identity). Consumers must hand-edit frontmatter, which bypasses validation and atomic publication - the exact thing the tool exists to prevent.

Scope: extend `patch` to `depends_on` and `related` (set/replace full lists), keeping number immutable and priority as-is. Candidate complete-ledger validation already enforces referential integrity, no cycles, and schema-2 dependency rules, so the patch layer only needs request-shape validation plus the existing CAS/lock machinery. Update the mutation contract section 8, the oracle's independent validPatchRequest mirror, and conformance fixtures. Decide and document whether a relations patch on a claimed item stays refused (it should - same as today).

Acceptance:
- The dependent-disposition kill flow completes end-to-end in-band on a fixture: patch dependent's depends_on -> related, then kill the target; no hand edits.
- Patch refuses a relations edit that would create a cycle, a dangling reference, or violate schema-2 done-dependency rules (candidate-invalid, ledger untouched).
- Oracle and core stay in exact agreement (mutation-guarded both directions); number remains unpatchable.
- Four-command gate green on both runtimes.
