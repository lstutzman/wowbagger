### The oracle decision — carry forward, do not silently repeat

The repo rule `spec/adapter-reference.js` is an independent oracle; never modify it.
Item 41 surfaced genuine **shared defects that also live in the oracle**: the oracle's
item-shape validator was schema-1-only while the repo had already migrated to schema 2,
and it shared the nonce/`source_id`/handoff coercions. A shipped-only fix would leave
shipped correctly diverging from the oracle, unpinned and dishonest about parity.

Lee authorized a narrow, one-time exception: for these confirmed shared defects, update
**both** the shipped code and the oracle in lockstep, and **pin each with a real
fixture** (a real schema-2 inspect vector, plus direct coercion tests). The same
coercion/schema gaps are treated as fixable in both copies from now on — but the oracle
must never be edited just to make a vector agree with a buggy implementation (that is
still the tautology this rule exists to prevent). A change to the oracle therefore
flags: is this a real shared gap, fixed in both and pinned, or is it papering over a
shipped bug? Only the former is allowed, and it should be called out in the commit.

This is also a **dogfooding finding**: the adapter's reference envelope validation was
never upgraded when the repo took schema 2, so conformance fixtures stayed schema-1 and
could not see that real (schema-2) `inspect`s were being refused. When schemas change,
check the adapter reference validators too, not just the core.

## The thing worth knowing

**A green conformance number on this runner has been wrong three times.** Each time it
reported `183/183 pass` while measuring nothing real:

1. It never touched the shipped entrypoint. Proved by deleting the trailing LF from the
   bootstrap response and watching conformance stay green while the real wire tests
   failed 18 of 20.
2. It launched real core children for the `negative-capability` cases, whose entire
   obligation is that no launch occurs.
3. It enforced no-launch at the injection point only, so a child spawned as an ignored
   side effect was invisible.

Every one was caught by an adversarial pass that assumed the previous conclusion was
wrong. None by the implementation work that produced it.

**So do not trust the number. Trust that it can fail.** Before believing any conformance
result, break something and confirm the run goes red:

| Mutation | Expected |
|---|---|
| Insert an awaited real core child launch as an ignored side effect | 4 negative-capability cases red |
| Clamp the child-output byte counter so overflow is never detected | `bounded-output` red |
| Remove the trailing LF from `writeBootstrapResponse` | runner rejects the wire |
| Remove one byte from forwarded core stdout | 3 equivalence cases red |
| Reverse declared protocol instruction order | `instruction-input` red |

## Standing rules

- **`TMPDIR=/tmp` on every test command.** Without it the lock socket path exceeds the
  macOS limit and runs fail for an environmental reason. `npm run check` does not set it
  and therefore fails by default — a known one-line defect, unfiled.
- **Never `git stash` here.** Several worktrees share one stash stack.
- **`spec/adapter-reference.js` is an independent oracle.** Never import it into `src/`
  (that makes the vectors tautological). Never modify it to make a vector agree with a
  buggy implementation. The single authorized exception is recorded in this handoff
  (`The oracle decision` section): a *shared* confirmed defect — present in both copies —
  may be fixed in both in lockstep and pinned by a real fixture, and that must be called
  out in the commit.
- **`src/` imports nothing from `test/` or `spec/`.**
- **The fixtures are normative.** Where contract prose and a fixture disagree, the
  fixture wins. Changing a vector to match an implementation is how a defect becomes a
  passing number — if a fixture fails and no contract clause makes it wrong, the code is
  wrong.
- **Coverage is judged by mutation**, not counts. Break each guard, confirm a test goes
  red. This repository has shipped inert guards more than once.
- Node 20 lives at `/opt/homebrew/opt/node@20/bin/node`, not on PATH.

## Ledger friction found by dogfooding

Four gaps surfaced while using wowbagger on itself. None is filed; all are real.

- **An item cannot be marked deferred/held.** There is no `deferred` status, no defer
transition edge, and `snoozed_until` is set only at `create`. Item 22's deferral had to
be logged in this handoff rather than in the ledger (this is the same gap as the
"change of direction" bullet below). Being unable to park an item in-band is a real
coordination gap.
- **Relations cannot be edited.** `patch` accepts exactly `number` and `priority`. Items
  37, 38 and 39 were filed with `depends_on` where `related` was correct, and there is no
  supported way to fix them.
- **A change of direction cannot be recorded.** Decisions attach only to edges that
  append evidence, and `backlog → in-progress` appends none. Item 44's reversal had to
  live in a design document instead.
- **`create` accepts an item with no `number`**, producing a handle-less item despite
  item 28 having established that every item gets one.

These four are filed as one new backlog item (the deferral gap, raised by item 22) so
they are tracked rather than left in a transcript.
